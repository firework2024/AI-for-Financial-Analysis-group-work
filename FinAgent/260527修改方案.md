# 一、总体目标

你们要把现在的财务分析智能体从：

```text
指标 → LLM 直接总结正负面信号
```

改成：

```text
指标 → 规则识别结构化信号 → LLM 审核解释 → 输出可追溯结论
```

核心变化不是多写 prompt，而是重构 LLM 在工作流中的角色。

原来：

```text
LLM = 分析者
```

改成：

```text
规则引擎 = 初级财务分析师，负责扫描所有指标
LLM = 高级财务分析师，负责审核、归纳、解释、润色
```

这样既保留 AI，又避免 AI 漏判和乱判。

---

# 二、建议的模块结构

你们现在的 `financial_analysis.py` 已经承担了太多事情：计算指标、调用 LLM、本地规则判断、输出结论。建议拆成四层。

```text
financial_analysis.py
    主入口，协调分析流程

metrics.py 或继续保留在 financial_analysis.py
    计算基础指标

signal_rules.py
    识别结构化财务信号

signal_combinations.py
    识别异常组合信号

llm.py
    LLM 审核、合并、解释信号
```

如果不想改太多文件，也可以先只新增一个文件：

```text
FinAgent/finagent/signals.py
```

里面放：

```python
detect_structured_signals()
detect_combination_signals()
summarize_signal_matrix()
```

然后让 `financial_analysis.py` 调用它。

# 三、第一步：把财务分析框架固化成几大模块

现在你们的指标已经比较丰富，包括收入、归母净利润、经营现金流、毛利率、收现比、净现比、自由现金流、流动比率、速动比率、资产负债率、ROE、ROA、周转率等。

建议把所有信号固定归入 6 类：

| 类别       | 英文字段               | 分析重点                                 |
| ---------- | ---------------------- | ---------------------------------------- |
| 成长性     | `growth`               | 收入、利润、现金流是否增长               |
| 盈利能力   | `profitability`        | 毛利率、净利率、ROE、ROA                 |
| 现金流质量 | `cash_quality`         | 收现比、净现比、自由现金流               |
| 偿债能力   | `solvency`             | 资产负债率、流动比率、速动比率、有息负债 |
| 营运效率   | `operating_efficiency` | 存货、应收、资产周转                     |
| 利润质量   | `earnings_quality`     | 扣非利润、现金流与利润匹配、非经常性影响 |

这样每个信号都有明确归属，后续报告也可以按模块展示。

建议输出结构：

```python
{
    "category": "cash_quality",
    "category_cn": "现金流质量",
    "signals": [...]
}
```

# 四、第二步：把正负面文本改成结构化信号

现在输出是：

```python
positive_signals = [...]
negative_signals = [...]
```

建议改成：

```python
structured_signals = [
    {
        "id": "cash_quality_001",
        "category": "cash_quality",
        "metric": "cash_to_profit",
        "metric_cn": "净现比",
        "polarity": "negative",
        "severity": "high",
        "value": 0.42,
        "threshold": "低于 0.5",
        "year": 2023,
        "description": "净现比较低，利润转化为经营现金流的能力偏弱。",
        "evidence": "2023 年净现比为 0.42，低于 0.5 的高风险阈值。",
        "confidence": "high",
        "source_fields": [
            "cash_flow_from_operating_activities",
            "net_profit"
        ]
    }
]
```

这一步非常关键。因为有了结构化信号之后，你们才能做到：

```text
可排序
可过滤
可解释
可验证
可输入 LLM
可输入风险评级模型
可做前端展示
```

而不是一堆不可控的自然语言句子。

# 五、第三步：增加信号强度

不要只判断 positive / negative。要给每个信号加 `severity`：

```text
low
medium
high
critical
```

建议规则如下。

## 现金流质量

| 指标       | 条件         | 方向     | 强度   |
| ---------- | ------------ | -------- | ------ |
| 收现比     | ≥ 1.0        | positive | medium |
| 收现比     | 0.8–1.0      | neutral  | low    |
| 收现比     | 0.6–0.8      | negative | medium |
| 收现比     | < 0.6        | negative | high   |
| 净现比     | ≥ 1.0        | positive | high   |
| 净现比     | 0.8–1.0      | neutral  | low    |
| 净现比     | 0.5–0.8      | negative | medium |
| 净现比     | < 0.5        | negative | high   |
| 自由现金流 | 连续为正     | positive | medium |
| 自由现金流 | 最新一年为负 | negative | medium |
| 自由现金流 | 连续两年为负 | negative | high   |

## 偿债能力

| 指标                     | 条件     | 方向     | 强度   |
| ------------------------ | -------- | -------- | ------ |
| 资产负债率               | < 40%    | positive | medium |
| 资产负债率               | 40%–60%  | neutral  | low    |
| 资产负债率               | 60%–75%  | negative | medium |
| 资产负债率               | > 75%    | negative | high   |
| 流动比率                 | < 1.0    | negative | high   |
| 速动比率                 | < 0.7    | negative | medium |
| 有息负债上升且现金流下降 | negative | high     |        |

## 营运效率

| 指标                             | 条件     | 方向   | 强度 |
| -------------------------------- | -------- | ------ | ---- |
| 应收账款增速 ≤ 收入增速          | positive | medium |      |
| 应收账款增速高于收入增速 0–20pct | negative | medium |      |
| 应收账款增速高于收入增速 >20pct  | negative | high   |      |
| 存货增速高于收入增速 >20pct      | negative | high   |      |
| 应收周转率下降                   | negative | medium |      |
| 存货周转率下降                   | negative | medium |      |

## 成长性

| 指标               | 条件     | 方向   | 强度 |
| ------------------ | -------- | ------ | ---- |
| 收入增长 > 10%     | positive | medium |      |
| 收入连续两年增长   | positive | medium |      |
| 收入负增长         | negative | medium |      |
| 收入连续两年下降   | negative | high   |      |
| 净利润负增长       | negative | medium |      |
| 净利润连续两年下降 | negative | high   |      |

# 六、第四步：增加异常组合识别

这是你们改造中最有价值的部分。单个指标只能说明局部问题，组合信号才能体现真正的财务分析能力。

建议至少做 8 个组合规则。

## 1. 收入增长但现金流恶化

```text
收入增长率 > 10%
且 净现比 < 0.8 或 经营现金流下降
```

输出：

```text
收入增长与现金流表现不匹配，收入增长质量存疑。
```

强度：

```text
如果净现比 < 0.5，则 high
否则 medium
```

## 2. 利润增长但经营现金流下降

```text
归母净利润增长率 > 0
且 经营现金流增长率 < 0
```

输出：

```text
利润增长未同步转化为经营现金流，利润质量需关注。
```

## 3. 应收账款和存货同时快于收入

```text
应收账款增速 > 收入增速
且 存货增速 > 收入增速
```

输出：

```text
营运资本占用加重，可能存在回款压力和库存压力。
```

## 4. 毛利率下降且费用率上升

```text
毛利率下降
且 销售费用率 / 管理费用率 / 财务费用率上升
```

输出：

```text
盈利能力受到毛利率和费用率双重挤压。
```

## 5. 资产负债率上升且现金流下降

```text
资产负债率上升
且 经营现金流下降
```

输出：

```text
杠杆压力与现金流压力同时上升，偿债安全边际下降。
```

## 6. 净利润增长但扣非净利润下降

```text
归母净利润增长率 > 0
且 扣非净利润增长率 < 0
```

输出：

```text
利润增长可能受到非经常性损益影响，可持续性不足。
```

## 7. 收入下降但存货上升

```text
收入增长率 < 0
且 存货增长率 > 0
```

输出：

```text
收入下滑同时库存上升，可能存在需求走弱或库存积压风险。
```

## 8. 高资本开支但现金流不足

```text
资本开支强度较高
且 自由现金流为负
```

输出：

```text
资本开支对现金流形成压力，扩张活动可能削弱自由现金流。
```

这些组合信号可以作为 `type = "compound"` 的信号。

例如：

```python
{
    "id": "compound_001",
    "type": "compound",
    "category": "earnings_quality",
    "polarity": "negative",
    "severity": "high",
    "description": "收入增长与现金流表现不匹配，收入增长质量存疑。",
    "evidence": "2023 年收入增长 18.4%，但经营现金流下降 22.1%，净现比仅为 0.46。",
    "related_metrics": [
        "revenue_growth",
        "cash_flow_from_operating_activities_growth",
        "cash_to_profit"
    ]
}
```

# 七、第五步：让 LLM 审核信号，而不是从零分析

这是核心改造。

当前逻辑是：

```text
财务证据 + 知识框架 → LLM → 正负面信号
```

建议改成：

```text
财务证据 + 结构化信号 + 知识框架 → LLM → 审核后的信号总结
```

LLM 的任务变成：

```text
1. 检查结构化信号是否存在明显冲突；
2. 合并重复信号；
3. 对 high severity 信号优先解释；
4. 根据财务框架生成专业表述；
5. 不得新增没有证据支持的结论；
6. 不得删除规则引擎识别出的 high severity 信号；
7. 输出仍然必须是 JSON。
```

系统提示词可以这样写：

```text
你是财务信号审核智能体，而不是自由分析师。

你会收到：
1. 公司上下文；
2. 财务指标证据；
3. 规则引擎识别出的结构化财务信号；
4. 财务分析知识框架。

你的任务：
- 审核结构化信号；
- 合并重复或高度相似的信号；
- 按重要性排序；
- 用专业、克制、可追溯的语言解释信号；
- 保留每个结论对应的 metric、value、evidence 和 severity；
- 不得新增没有证据支持的结论；
- 不得修改原始财务数据；
- 不得删除 severity 为 high 或 critical 的负面信号；
- 不得给出买入、卖出、持有建议。

请只输出 JSON。
```

输出格式建议固定为：

```json
{
  "reviewed_signals": [
    {
      "category": "cash_quality",
      "polarity": "negative",
      "severity": "high",
      "title": "利润现金含量偏弱",
      "explanation": "公司净现比较低，说明当期利润未充分转化为经营现金流。",
      "evidence": "2023 年净现比为 0.42，低于 0.5 的高风险阈值。",
      "metrics": ["cash_to_profit"],
      "confidence": "high"
    }
  ],
  "positive_signals": [
    "毛利率保持稳定，盈利能力未出现明显恶化。"
  ],
  "negative_signals": [
    "净现比较低，利润现金含量偏弱。"
  ],
  "key_risks": [
    "现金流质量风险",
    "营运资本占用风险"
  ],
  "data_notes": [
    "2023 年部分字段使用年报文本回退，相关结论需谨慎解释。"
  ]
}
```

# 八、建议改造后的代码流程

在 `financial_analysis.py` 里，主函数可以改成这样：

```python
def analyze_financials(
    enriched_rows,
    metric_factor_values=None,
    company_context=None
):
    rows = sorted(enriched_rows, key=lambda item: item["year"])

    metrics = [_metrics_for_row(row) for row in rows]
    _add_trend_metrics(metrics)
    _apply_metric_factor_fallbacks(metrics, metric_factor_values or {})

    structured_signals = detect_structured_signals(rows, metrics)
    compound_signals = detect_compound_signals(rows, metrics)

    signal_pack = {
        "structured_signals": structured_signals,
        "compound_signals": compound_signals,
        "signal_summary": summarize_signals(
            structured_signals + compound_signals
        )
    }

    evidence = _build_llm_evidence(rows, metrics, company_context or {})
    evidence["signals"] = signal_pack

    if get_env("OPENAI_API_KEY"):
        try:
            analysis = financial_signal_review_agent(
                evidence=evidence,
                framework_text=load_financial_framework_excerpt(),
                company_context=company_context or {},
            )
            analysis["metrics"] = metrics
            analysis["raw_signals"] = signal_pack
            return analysis
        except Exception:
            pass

    return local_signal_review(signal_pack, metrics, rows)
```

注意这里的 LLM 函数不再叫：

```python
financial_analysis_agent()
```

而可以叫：

```python
financial_signal_review_agent()
```

语义更准确。

# 九、结构化信号识别函数设计

可以先从简单工具函数开始。

```python
def make_signal(
    *,
    category,
    metric,
    metric_cn,
    polarity,
    severity,
    value,
    threshold,
    year,
    description,
    evidence,
    source_fields=None,
    signal_type="single",
    confidence="high",
):
    return {
        "type": signal_type,
        "category": category,
        "metric": metric,
        "metric_cn": metric_cn,
        "polarity": polarity,
        "severity": severity,
        "value": value,
        "threshold": threshold,
        "year": year,
        "description": description,
        "evidence": evidence,
        "source_fields": source_fields or [],
        "confidence": confidence,
    }
```

然后逐类检测：

```python
def detect_cash_quality_signals(latest):

    cash_to_profit = latest.get("cash_to_profit")

        if cash_to_profit >= 1:
            signals.append(make_signal(
                category="cash_quality",
                metric="cash_to_profit",

                polarity="positive",
                severity="high",

        elif cash_to_profit < 0.5:
            signals.append(make_signal(
                category="cash_quality",
                metric="cash_to_profit",
                metric_cn="净现比",
                polarity="negative",
                severity="high",
                value=cash_to_profit,

            ))

    return signals
```

# 十、异常组合识别函数设计

示例：

```python
def detect_compound_signals(metrics):
    signals = []
    latest = metrics[-1]

    revenue_growth = latest.get("revenue_growth")
    ocf_growth = latest.get("cash_flow_from_operating_activities_growth")
    cash_to_profit = latest.get("cash_to_profit")

    if (
        revenue_growth is not None
        and revenue_growth > 0.10
        and (
            (ocf_growth is not None and ocf_growth < 0)
            or (cash_to_profit is not None and cash_to_profit < 0.8)
        )
    ):
        severity = "high" if cash_to_profit is not None and cash_to_profit < 0.5 else "medium"

        signals.append(make_signal(
            signal_type="compound",
            category="earnings_quality",
            metric="revenue_growth_vs_cash_flow",
            metric_cn="收入增长与现金流匹配度",
            polarity="negative",
            severity=severity,
            value={
                "revenue_growth": revenue_growth,
                "ocf_growth": ocf_growth,
                "cash_to_profit": cash_to_profit,
            },
            threshold="收入增长但现金流恶化或净现比低于 0.8",
            year=latest["year"],
            description="收入增长与现金流表现不匹配，收入增长质量存疑。",
            evidence=(
                f"{latest['year']} 年收入增长 {revenue_growth:.1%}，"
                f"经营现金流增长 {ocf_growth:.1%}，"
                f"净现比为 {cash_to_profit:.2f}。"
            ),
            source_fields=[
                "revenue",
                "cash_flow_from_operating_activities",
                "net_profit"
            ],
        ))

    return signals
```

# 十一、LLM 输出后如何保证不丢信号

你们担心 LLM 漏掉关键指标，所以还要加一个“后处理校验”。

规则：

```text
如果 raw_signals 里有 severity = high / critical 的 negative 信号，
但 LLM 的 reviewed_signals 没有覆盖它，
则自动追加到 reviewed_signals。
```

可以写：

```python
def enforce_required_signals(raw_signals, reviewed_signals):
    reviewed_evidence = " ".join(
        item.get("evidence", "") + item.get("explanation", "")
        for item in reviewed_signals
    )

    required = [
        s for s in raw_signals
        if s["polarity"] == "negative"
        and s["severity"] in ("high", "critical")
    ]

    for signal in required:
        metric = signal.get("metric")
        if metric and metric not in reviewed_evidence:
            reviewed_signals.append({
                "category": signal["category"],
                "polarity": signal["polarity"],
                "severity": signal["severity"],
                "title": signal["description"],
                "explanation": signal["description"],
                "evidence": signal["evidence"],
                "metrics": [metric],
                "confidence": signal.get("confidence", "medium"),
                "source": "rule_enforced"
            })

    return reviewed_signals
```

这样 LLM 就算漏了，也会被规则补回。

```python
{
    "positive_signals": [...],

```

其中：

```text
positive_signals / negative_signals
```

```text
reviewed_signals
raw_signals
key_risks
```

这样不会破坏现有工作流。
