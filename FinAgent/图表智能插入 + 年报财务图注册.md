# 图表智能插入 + 年报财务图注册

## Context

两份报告对比暴露了图表系统的两个独立问题：

1. **图表与正文"两张皮"**：正文由 LLM 先写好，图表随后由机械算法挂载。LLM 写作时不知道图会挂在哪，机械算法挂图时不动正文。结果正文和图之间没有任何桥接句。

2. **经营质量分析缺少年报财务图**：`revenue_profit_trend`、`profit_vs_cashflow`、`free_cashflow_trend`、`margin_roe_trend` 四张图已实现在 `chart_plots.py` 中，但从未注册到 `chart_catalog.py`——没有标题、没有 hint 关键词、不在任何章节的候选列表里。所以即使数据到位了，它们也永远不会被挂到报告中。

两个问题一并解决。总体改动量约 100 行新增代码 + 50 行配置。

---

## Part A：图表元数据生成（让后续智能体"看懂"图）

### 为什么需要这一步

当前 LLM 拿到的是 `{"profitability_factors": "charts/xxx.png"}`——只有文件路径。智能体要做出好的 placement 决策，需要知道每张图画了什么（系列名、时间范围、趋势方向、最新值）。

### 改什么

**文件**：`finagent/chart_plots.py`，在 `chart_agent()` 函数末尾新增

```python
def _build_chart_metadata(data: dict[str, Any], charts: dict[str, str]) -> dict[str, Any]:
    """为每张已生成的图表构建元数据，供后续 placement 智能体使用。"""
```

这个函数对 `charts` 字典中的每张图，根据其类型提取数据摘要：

**对于 factor 历史图**（profitability_factors, growth_factors, liquidity_factors, debt_ratio_trend）：
- 从 `data["factor_history"]["rows"]` 提取对应字段序列
- 输出：series_names（中文标签）、date_range（首尾日期）、trend（"上升"/"下降"/"分化"）、latest_values（最新值字典）

**对于行业对比图**（industry_profitability_compare, industry_growth_leverage_compare, industry_dbscan_anomaly）：
- 从 `data["industry_comparison"]` 提取
- 输出：peer_count、metrics_table（目标值/中位数/均值/分位）、dbscan_info（噪声点标记、簇规模、异常分数）

**对于年报财务图**（revenue_profit_trend, profit_vs_cashflow, free_cashflow_trend, margin_roe_trend）：
- 从 `data["annual_analysis"]["financial_data"]` 提取（workflow 格式）
- 输出：years、series_labels、values_by_year

**对于量价图**（price_volume, moving_averages, technical_indicators 等）：
- 从 `data["price"]["rows"]` 提取
- 输出：date_range、price_range、volume_range、technical_values（MA、RSI 等）

注意：`chart_pattern.py` 中的 `build_chart_pattern()` 已经做了类似的事，但它只输出"形状描述"字符串。新函数输出的是**结构化字典**，可以直接喂给 placement 智能体。

**在 `chart_agent()` 末尾调用**：
```python
data["_chart_metadata"] = _build_chart_metadata(data, charts)
```

这样元数据跟随 `data` 一路传递到 `_assemble_multi_report()`，不需要改任何函数签名。

## Part C：智能体图表插入

### 设计决策：替换 `apply_chart_placements` 还是包一层？

当前流程：
```
resolve_section_visuals() → placement dict（决定"哪些图去哪章"）
     ↓
apply_chart_placements()  → 机械插入（决定"插到章的哪个位置"）
```

`resolve_section_visuals()` 的职责是"哪些图去哪章"，这个逻辑已经是 LLM 驱动的（`visual_need_agent()`），而且做得还可以，不用改。

`apply_chart_placements()` 的职责是"插到章的哪个位置 + 怎么插"，当前是机械的。我们用智能体替代这一步。

**方案**：新增 `apply_chart_placements_agent()`，在 API 可用时走智能体路径，不可用时 fallback 到现有机械路径。

### 新函数设计

**文件**：`finagent/multi_report.py`，新增函数

```python
def apply_chart_placements_agent(
    sections: dict[str, str],
    charts: dict[str, str],
    placement: dict[str, Any],
    *,
    data: dict[str, Any] | None = None,
    figure_notes: dict[str, str] | None = None,
) -> tuple[dict[str, str], list[str]]:
```

**逻辑**：

```
对 placement["placements"] 中的每个 placement item：
  section_name = item["section"]
  section_text = sections.get(section_name)
  如果 section_text 不存在或为空 → 跳过
  
  assigned_charts = item["charts"]  # 分配给本章的图表列表
  
  # 为每张图组装元数据
  chart_meta_pool = {}
  for chart_name in assigned_charts:
      if chart_name in charts:
          chart_meta_pool[chart_name] = {
              "path": charts[chart_name],
              "caption": chart_caption(chart_name),
              "hints": _visual_subheading_hints(chart_name),
              "data_summary": _chart_data_summary(chart_name, data),  # 从 Part A 的元数据中取
          }
  
  如果 API 可用且 chart_meta_pool 非空：
      调用 placement_editor_agent(section_text, chart_meta_pool)
      → 返回修改后的 section_text（含图表块和桥接句）
  否则：
      走现有机械插入逻辑
```

### placement_editor_agent 的 prompt 设计

这个智能体做三件事：**判断位置 → 插入图块 → 补桥接句**。一次 LLM 调用来完成。

```
你是一个研究报告的图表排版编辑。你会收到：

1. 一个已完成写作的章节正文
2. 一组需要插入该章节的图表，每张图包含：
   - 图表标题（中文名称）
   - 图表文件路径
   - 提示关键词（用来定位图表与正文的关联）
   - 数据摘要（图表中画了什么数据、时间范围、趋势描述、最新值）

你的任务：
对每张图表，判断它应该插入到正文的哪个位置，并在插入点周围写 1-2 句桥接文本。

具体规则：
- 图表应该放在相关讨论之后。例如讨论毛利率趋势的段落后面放盈利能力因子图。
- 图表不能放在小节标题之前。
- 如果某个小节内容和图表高度相关，把图表放在该小节末尾。
- 图表之间至少间隔 2-3 段文字，不要连续堆积多张图。
- 在插入图表的附近（上一句或下一句），补一句桥接文本。例如：
  - "如下方图表所示，毛利率从 X% 持续上升至 Y%"
  - "从下图可以直观看到，经营现金流与净利润的剪刀差在 2024 年后收窄"
  - 桥接句要和上下文风格一致，数据必须来自图表的数据摘要，不能编造
- 图表本身的 Markdown 块（#### 图 · XXX ...）不要修改内容，只改它的位置和周围的正文

输出：直接输出完整的修改后章节正文（Markdown），不要加"好的""修改完毕"等开场白。
```

### 插入位置

在 `_assemble_multi_report()` 中（约 `multiagent.py:800`），把：

```python
result, omitted = apply_chart_placements(normalized, charts, placement, data=data)
```

改为：

```python
result, omitted = apply_chart_placements_agent(
    normalized, charts, placement,
    data=data, figure_notes=figure_notes,
)
```

`apply_chart_placements_agent` 内部：如果 `data.get("_chart_metadata")` 存在且 API 可用 → 走智能体路径；否则 → 走现有机械路径（即调用原来的 `apply_chart_placements` 逻辑）。

### 需要额外处理的问题

**问题 1：智能体可能不返回完整正文**

LLM 有时会截断输出（只输出被修改的段落，而不是完整章节）。对策：输出校验——检查返回的文本是否包含原始正文中的主要小节标题。如果不完整，fallback 到机械插入。

**问题 2：图表数量为 0 的章节**

如果某个章节没有分配到任何图表，跳过智能体，直接保持原文。

**问题 3：token 消耗**

经营质量分析章节约 3000-5000 字（约 2000-3500 token），加上 5-7 张图的元数据（每张约 200 token），总输入约 3000-5000 token。一次 LLM 调用，约 2-5 秒延迟。**只对"经营质量分析"章节启用智能体插入**，量价、资金、宏观章节仍用机械插入（它们的图比较简单，图文关联不需要太强）。

这样做的好处：风险可控（改动只在"经营质量分析"一个章节生效），后续可以逐步扩展到其他章节。
