# 图表智能插入 + 年报财务图注册 — 方案评审与纠正

## 背景

原方案（[图表智能插入 + 年报财务图注册.md](./图表智能插入%20+%20年报财务图注册.md)）提出了三个改动方向：
- **Part A**：在 `chart_plots.py` 新增 `_build_chart_metadata()`，为每张图生成结构化元数据
- **Part B**：在 `chart_catalog.py` 注册 `revenue_profit_trend` 等4张年报财务图
- **Part C**：在 `multi_report.py` 新增智能体驱动的 `apply_chart_placements_agent()`

代码评审发现 **3个严重缺陷、4个高危缺陷**。本文件记录修复方案。

---

## 🔴 严重缺陷及其修复

### 缺陷1：机械降级路径下4张年报图没有图注

**问题**：原方案明确"不需要为这4张图添加 `CHART_DATA_SOURCE`"，但没有添加 `CHART_BRIEF_NOTES`。机械降级路径的图注生成链中，`fallback_chart_note()` → `build_chart_pattern()` → `CHART_DATA_SOURCE.get(name)` 返回空 → 图注为"曲线形态待数据补充" → `_sanitize_figure_note` 过滤掉 → 最终图块没有任何图注。

**修复**：在 [chart_catalog.py](finagent/chart_catalog.py) 的 `CHART_BRIEF_NOTES` 中添加4条条目：

```python
"revenue_profit_trend": "近年营收（柱）与归母净利润（折线）双轴对比，观察收入规模与盈利能力的匹配度。",
"profit_vs_cashflow": "归母净利润与经营现金流净额多年对比，用于判断利润的现金含量（净现比）。",
"free_cashflow_trend": "自由现金流多年趋势（正值/负值着色），反映企业可支配现金的变化方向。",
"margin_roe_trend": "毛利率与 ROE 多年双轴走势，观察盈利能力和股东回报的变动轨迹。",
```

`_sanitize_figure_note` 的内部逻辑是 `str(note or CHART_BRIEF_NOTES.get(chart_name) or "").strip()` — 当 `note` 为 falsy 时自动回退到 `CHART_BRIEF_NOTES`，所以无需改调用代码。

### 缺陷2：LLM 可以直接改毁图表 Markdown 块

**问题**：原方案把完整的图表 Markdown 块（`#### 图 · XXX\n\n![](...)\n\n**图注**...`）直接交给 LLM，只靠 prompt 约束"不要修改"。LLM 有多种方式破坏格式：改 `####` 级别、丢失图片路径、数据编造。

**修复**：采用**占位符机制**。LLM 的输出中只出现 `{{CHART:revenue_profit_trend}}` 占位符，程序在 LLM 输出后替换为完整的 Markdown 图块。

实现细节（[multi_report.py](finagent/multi_report.py)）：

```
apply_chart_placements_agent()
  → _placement_editor_agent()        # LLM 只输出 {anchor, bridge_sentence}
  → _insert_agent_placement()        # 在正文中插入 bridge + {{CHART:xxx}}
  → _resolve_placeholders()          # 正则替换 {{CHART:xxx}} → 完整 Markdown 图块
```

LLM **根本不接触**图表 Markdown 块，无法破坏。

### 缺陷3：单次 LLM 调用输出极易截断

**问题**：原方案要求 LLM 一次完成"判断所有图位置 + 写所有桥接句 + 输出完整章节"，输出可能膨胀到 4000-6000+ 字。默认 `max_tokens=2600` 会截断。

**修复**：**每张图一次轻量调用**。`_placement_editor_agent()` 只处理一张图，输出仅 `{"anchor": "...", "bridge_sentence": "..."}`，约 200-400 token。无截断风险。

## 🟠 高危缺陷及其修复

### 缺陷4：Token 估算偏低 2-3 倍

**问题**：方案估算约 3000-5000 token/次，实际可达 5000-10000。

**修复**：采用每个图表独立轻量调用后，每次调用仅 ~500-1500 input token 和 ~200-400 output token，不构成压力。

### 缺陷5：输出校验逻辑不足以兜住错误

**问题**：原方案只检查"返回文本是否包含原始标题"，无法检测：图表块缺失、图片路径篡改、桥接句数据编造。

**修复**：三层校验 `_validate_agent_output()`（[multi_report.py](finagent/multi_report.py)）：

| Layer | 检查项 | 方法 |
|-------|--------|------|
| 1 | 占位符已全部解析 | 正则 `\{\{CHART:(\w+)\}\}` 找残余 |
| 2 | 子标题完整性 | diff `####` 标题集合 |
| 3 | 正文保留率 | 段落 Jaccard 相似度 > 55% |

任意层不通过 → 该整章退化为机械插入。

### 缺陷6：`refresh_data` 但 `refresh_charts` 时元数据静默丢失

**问题**：`refinement_loop` 中 `refresh_data` 创建新 data dict（不含 `_chart_metadata`），之后 `_assemble_multi_report` 找不到元数据，静默退化到机械插入。

**修复**：在 [multiagent.py](finagent/multiagent.py) 中加守卫：

```python
if requests.get("refresh_data"):
    data = data_executor_agent(...)
    data.pop("_chart_metadata", None)  # 显式清除旧元数据
```

同时确保 `refresh_charts` 路径重新注入 `_chart_metadata`（已在 `chart_agent()` 末尾统一处理）。

### 缺陷7：`placement_editor_agent` 完全不存在

**问题**：原方案引用了未实现的函数。

**修复**：完整实现，含所有辅助函数（见 Part C 实现清单）。

## 🟡 中危缺陷及其修复

### 缺陷8：缺少 `CHART_BRIEF_NOTES`

→ 见缺陷1修复。

### 缺陷9：硬编码"只对经营质量分析启用"

**修复**：参数化 `agent_sections`：

```python
def apply_chart_placements_agent(
    ...,
    agent_sections: frozenset[str] | None = None,  # 默认 {"经营质量分析"}
)
```

### 缺陷10：数据传输盲区

**修复**：确认 `_chart_metadata` 不会被传入写作 prompt（`_compact_data_for_prompt` 不包含 `annual_analysis` 的原始字段以外的 key）。`chart_agent()` 末尾直接 `data["_chart_metadata"] = ...` 修改传入的 dict 引用。

### 数据流

```
chart_agent(data)                           # 在末尾注入 data["_chart_metadata"]
    ↓
_assemble_multi_report(data, charts, ...)   # data 带 _chart_metadata
    ↓
apply_chart_placements_agent(...)           # 读取 data["_chart_metadata"]
    ├─ API OK + section in agent_sections + chart has metadata
    │   → LLM 每图一次调用 → 占位符插入 → 替换 → 3层校验
    └─ 否则 → 机械插入原逻辑
```

### 测试结果

- 全量测试：157 passed, 1 failed（预存在 GBK 编码问题，与本次改动无关）
- 验证的边界：
  - `_build_chart_metadata` 空数据/因子历史/年报财务/行业对比四种路径
  - `apply_chart_placements_agent` 机械降级路径（无 API Key）
  - 4张新图的注册完整性（`CHART_CAPTIONS`/`BRIEF_NOTES`/`HINTS`/候选列表）
  - 与原 `apply_chart_placements` 的行为一致性
